# `paper_1_transfer/results` — what the manuscript reads

Every number in Paper 1 comes from a file in this folder. Nothing here is written by hand,
nothing is edited by hand, and no statistic is transcribed into the `.qmd`. The manuscript
reads these files through inline R, so re-rendering is what updates the reported values.
If a number in the paper looks wrong, the file is where to look, and the script that wrote
the file is where to fix it.

## Naming

| Pattern | What it is |
|---------|------------|
| `_*.csv` | A machine-written summary table the manuscript reads. The leading underscore marks it as an artefact of the pipeline and sorts the whole set together. |
| `<property>_decoding_*.csv` | Decoding output from step 9, one set per property: the pooled time-course, the temporal generalisation, and the cross-language and cross-property generalisations. |
| `*.rds` | Fitted brms objects and their per-model summaries. **Not in version control** (`.gitignore` excludes `results/*.rds`), because they are large and are regenerated by the model scripts. Step 5 reads them to build the pooled CSVs. |
| `CODEBOOK.md` | Column-level codebook, machine-written by `../../_shared/R/write_codebook.R` from the file headers and `_shared/R/codebook_descriptions.csv`. Regenerate after pulling the CSVs. |

## What writes what

The pipeline table in [`../README.md`](../README.md#pipeline-scripts-run-in-order) maps
each stage to the files it produces, and is the authority. In outline, steps 0 to 0d write
the participant-flow, retention and gate tables (`_sample_flow.csv`, `_participants.csv`,
`_participants_other_languages.csv`, `_participant_matrix.csv`, `_flow_inconsistencies.csv`,
`_erp_trial_retention.csv`, `_misfiltered_share.csv`, `_training_gate_flow.csv`), step 1b
writes the RSVP timing census as one row (`_rsvp_timing.csv`), step 2 writes the accuracy
screens (`_accuracy_rt_screen.csv`, `_accuracy_sentence_inventory.csv`,
`_accuracy_input_gaps.csv`), and step 5 writes the pooled convergence, posterior-summary and
fit-metadata tables, the retention contrasts, the first-session language advantage and the
prior sensitivity (`_pooled_convergence.csv`, `_pooled_posterior_summaries.csv`,
`_pooled_fit_metadata.csv`, `_retention_contrasts.csv`,
`_first_session_language_advantage.csv`, `_prior_sensitivity.csv`) from the fitted `.rds`.
Steps 7 to 7c write the grand-average waveform and electrode tables, steps 8 and 9 write
the decoding CSVs, and step 10 writes the literature-trend counts. The light descriptive
tables of steps 0, 0c and 2 are regenerated on the cluster by
`../hpc/00_descriptives.slurm`, which runs those three scripts with every variant switch
unset.

Six files are written into both papers' `results/`, so that the two papers cannot report
different cohort numbers: step 0 writes `_sample_flow.csv`, `_participants.csv` and
`_participants_other_languages.csv`, step 0b writes `_participant_matrix.csv` and
`_flow_inconsistencies.csv`, and step 0d writes `_training_gate_flow.csv`.

An earlier marker file, `_exclusions.csv`, has been removed from the working tree.
Nothing wrote or read it after the exclusion check was rebuilt to key on the per-fit
records in `_pooled_fit_metadata.csv` (columns `exclusion_applied` and
`misfiltered_rows`).

`_provenance.csv` is the exception in kind. It is written at fit time by
`../../_shared/R/04_provenance.R` and holds the R and platform versions, the versions of
every package in `LES_PROVENANCE_PKGS` (`_shared/R/04_provenance.R`), the CmdStan version
and the seeds. Where any other account of the environment disagrees with it, it is right.

## Reading the decoding files

Each row of a `*_decoding_timecourse.csv` carries an `inference` column saying which family
it belongs to. Only the pooled all-sessions block is confirmatory, one family per property,
and only its rows are corrected by the second-layer BH-FDR that `cluster_p_fdr` reports.
The session-resolved, session-by-language, cross-language, cross-property and
temporal-generalisation rows are exploratory breakdowns and enter no correction family.
The `n_perm` column can differ between the two strata, because a confirmatory block may be
recomputed at a higher permutation count on its own; see
[`../scripts/README.md`](../scripts/README.md).

## Reproducing them

None of these files is produced at render time. Run the pipeline (see
[`../scripts/README.md`](../scripts/README.md) and [`../hpc/README.md`](../hpc/README.md)),
pull the CSVs back to the rendering box, and re-render. Before the fits are in place, the
manuscript prints `*[pending model fit]*` placeholders and a "Reproducible draft" callout,
which is the intended behaviour.
