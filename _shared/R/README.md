# `_shared/R` — the modules both pipelines source

Ten modules, sourced by name from each paper's `scripts/` or from the manuscripts' setup
chunks, and four standalone scripts, `write_codebook.R`, `write_data_manifest.R`,
`count_docx_words.R` and `tally_issues.R`, run by hand. They are not a package
and there is nothing to install. Each pipeline script sources `00_paths.R` before any other
module, directly or through the script it builds on, because that module anchors the
project root. A script that uses its paper's `_config.R` sources it after the shared
modules it loads at its head, and `_config.R` sources `00_paths.R` and `03_data_manifest.R`
itself when they are absent. Paper 2's `06b_recover_provenance.R` sources
`01_bayesian_settings.R` later, in the block that runs when the script is called directly.
Paper 2's `02_extract_learning_trajectory.R` sources Paper 1's `02_extract_accuracy.R` after
its own `_config.R`, and that script loads `00_paths.R`, `03_data_manifest.R` and Paper 1's
`_config.R` again. Two modules share the `06_` prefix. `06_helpers.R` serves the pipeline scripts and
`06_manuscript_helpers.R` the manuscripts.

| Module | What it provides |
|--------|------------------|
| `00_paths.R` | Every path in the compendium. `data_path()`, `paper1_results()`, `paper2_derived()` and the rest resolve against the project root, which `here::here()` finds by searching upwards from the working directory for any of its root markers (`LESS Project.Rproj`, `renv.lock` and `.git` here; the cluster copy has the `.Rproj` file alone), falling back to the working directory itself. On the cluster the roots come from `LES_DATA_ROOT` and `LES_STORE`; either variable set but empty stops the run. This module is what makes the pipelines runnable from any working directory on any machine, and it replaced the legacy scripts' hard-coded container paths. |
| `01_bayesian_settings.R` | The brms and Stan configuration that must be identical across the two papers: the cmdstanr backend with `reduce_sum` threading, iteration and chain counts, and the literature-derived priors. Each block cites the source that motivates it, and section 1 says why a rerun reproduces the reported summaries to within Monte Carlo error rather than draw for draw. `les_brm()` refuses a cached fit that brms would reuse although it was sampled with other chains, seed or control settings, or fewer iterations. The `LES_PRIOR_SET` (`informative` or `weak`; any other value stops), `LES_ITER_WARMUP`, `LES_ITER_SAMPLING` and `LES_REQUIRE_CMDSTANR=1` environment switches are read here; `LES_PRIOR_PREDICTIVE=1` is read by Paper 1's fitting scripts, which then call `les_prior_predictive_check()`. |
| `02_diagnostics.R` | The single convergence standard both papers report against. `les_check_convergence()` records a pass/fail flag on rank-normalised split-R̂ < 1.01, bulk and tail ESS, and divergences, with thresholds from Vehtari et al. (2021). The flag is reported, not enforced: the pooling steps count failures and the manuscripts mark a failing model. `les_summarise_draw_vector()` is the one definition of the median, equal-tailed interval and probability of direction, which `les_posterior_summary()` applies to each coefficient. Also `les_save_ppc()`, `les_prior_predictive_check()` and `les_prior_sensitivity()`. The `LES_TREEDEPTH_FROM_CONTROL=1` switch, which reports the tree-depth count under the cmdstanr backend, is read here. |
| `03_data_manifest.R` | The map from the logical data names to their real folders, so a change in the physical layout is absorbed here instead of in every script. It also holds the read-only contract: `les_assert_readonly_data()` stops the script when a path it is given resolves inside `data/`. The extraction stages and the shared writers (`les_brm()`'s cache, `02_diagnostics.R`, `04_provenance.R`, `07_task_durations.R`) pass their paths through it; some pooling and fit-metadata writes in the paper scripts do not yet. `les_participant_key()` is the one reader of the participant key, with checks for duplicate IDs, a lab ID without a mini-language and a parity mismatch. `les_data_list()` and `les_data_source()` list and open files of the data tree on disk or, in the sparse rendering checkout, from the committed copy. The scripts reach the tree through the accessors listed in its header. Paper 1's `08_extract_decoding_matrices.R` also calls `data_path()` directly, to fingerprint the legacy import scripts under `data/` that shape the decoding tensor. |
| `04_provenance.R` | Writes `results/_provenance.csv` at fit time, recording the versions actually loaded by that run, the seeds, the sampling configuration and variant switches in force, the CmdStan optimisation pin, the loaded environment modules and an MD5 of the analysis code. `les_check_lockfile()` compares the loaded library with `renv.lock` (warning, or stopping under `LES_REQUIRE_LOCKFILE=1`), and its outcome is recorded too. A lockfile alone cannot do this job, because it records what a library held when it was snapshotted, carries no seeds, and cannot cover CmdStan or the compiler. |
| `05_funnel.R` | The shared participant-flow figure generator, `les_flow()`: a monochrome CONSORT-style diagram of enrolment split into the two mini-language arms (Mini-Norwegian on the left), each arm's attendance at every session, and the analysis samples, either per arm (Paper 1) or as a nested pooled chain with the exclusions at each step (Paper 2). Every derived count is computed from the counts passed in. The drawing is shared so the two figures look identical; the content is paper-specific, because the two papers draw on different stages of the same cohort. It replaced the ghost-bar `les_funnel()`, whose step labels misstated attrition where the stages were not nested. |
| `06_helpers.R` | Small pipeline helpers: `les_zscore()`, the z-score standardiser Paper 2's scripts call (always with `all_na = "zero"`; Paper 1's extraction scripts 01 and 02 still carry private `.les_scale()` copies with the rules of `all_na = "na"`), and `les_participant_folds()`, the participant-grouped fold builder used by Paper 2's projpred selection and its participant-grouped model comparison. Sourced with `source(here::here("_shared", "R", "06_helpers.R"))`. |
| `06_manuscript_helpers.R` | The reporting helpers that both manuscripts and the Paper 2 supplement source in their setup chunks, which make up the house style of every figure and table. It defines the colour, shape and level-order registry (`LES_LANG_COLS` and the other `LES_*` constants, one meaning per hue), the figure themes `les_theme()`, `les_forest_theme()` and `les_row_title_theme()`, the placeholder `les_placeholder()` for a withheld figure, the scales and label formatters (`les_scale_language()`, `les_lab_num()`, `les_lab_prop()`, `les_minus()` and the rest), the shared layers (`les_ref_h()`, `les_judgement_layers()`, `les_blank_cells()`, `les_erp_frame()` and `les_erp_layers()`), the diverging scale `les_div`, and `les_grid_table()`, the one writer of manuscript tables, with its cell formatters. It also holds the `apa_num()` number formatter (papaja's, which the file requires), the probability-of-direction formatters `.fmt_pd()` and `.pd_math()` that both papers print with, and `.read_csv_if()`, which reads a results CSV and returns `NULL` when the file is absent. `prov()`, `flow_n()` and `pstat()` fill inline values from the provenance, participant-flow and demographics tables that each document loads through `.read_csv_if()`. |
| `07_task_durations.R` | The observed durations of the home tasks and the lab-session phases that both manuscripts report. It reads the Gorilla executive-function exports through the manifest accessors, the OpenSesame lab-session files through `08_lab_logs.R` and the participant key through `les_participant_key()`, and when those folders or files are absent from the sparse checkout it lists and reads the committed copies through `git`; a read that fails either way stops the run before anything is written. `les_write_task_duration_artifacts()`, called by Paper 2's step 13 (`13_extract_task_durations.R`), writes `_task_durations_home.csv` and `_task_durations_lab.csv` into both papers' `results/`; neither table carries the Gorilla home ID. The two semicolon-delimited Session-4 logs give no rows under the comma rule the committed table was built with, and the extractor warns about them; `LES_DURATIONS_SNIFF_DELIM=1` reads them. Its two plotting helpers, `les_task_duration_home_plot()` and `les_task_duration_lab_plot()`, draw participants as points under a box per session, one panel per task or phase, on a logarithmic axis; the home figure marks the few idle-gap durations beyond the axis with a computed count. They call `les_theme()` and `les_placeholder()`, so `06_manuscript_helpers.R` has to be sourced before they are called, and their `base_size` defaults to the manuscripts' `LES_FIG_BASE_SIZE`. |
| `08_lab_logs.R` | One listing rule and one reader for the OpenSesame lab-session logs, for the four scripts that read them (Paper 1's 00d, 01b and 02, and `07_task_durations.R`): `les_lab_log_files()` lists every `*.csv` of a session folder with the lab ID and split part parsed from the name by one pattern, and `les_read_lab_log()` reads a log as text with its delimiter taken from the header line, or with a fixed delimiter where a script must reproduce an output built with the comma-only reader. |
| `write_codebook.R` | Opt-in, run by hand on the rendering box after the CSVs are pulled. Lists every manuscript-facing results CSV, reads its header and column classes, joins `codebook_descriptions.csv` and writes `results/CODEBOOK.md` in each paper. Not called by any pipeline stage. |
| `write_data_manifest.R` | Opt-in, run by hand. `write <file>` lists every tracked file under `data/` with its git blob id and the data tree id, from the index alone, so the sparse checkout is enough; `verify <file>` hashes a data copy (on the cluster, `$LES_DATA_ROOT`) the way git does, accepting CRLF where the commit holds LF, and exits with status 1 when a file is missing or differs. The data tree id is the input version a result can cite. Not called by any pipeline stage. |
| `count_docx_words.R` | Opt-in, run by hand on a rendered `.docx`. Counts the body words the way `paper_2_plasticity/journal_requirements.json` records them (`measured_2026_09_10`): from the Introduction's first paragraph to the first appendix heading, with a paragraph counted as table content only when it has a `w:tbl` ancestor. It prints each variant (math text in or out, a non-breaking space splitting words or not, the reference list in or out), the abstract's word count and the main-text figures and tables. It reads the abstract only when the docx carries it, which apaquarto's docx does for a folded `abstract: >-` and not for a block `abstract: \|`. Needs `xml2`. |
| `tally_issues.R` | Opt-in, run by hand. Counts the entries of `ISSUES.md` by status class (resolved, partly, open, author decision, deferred, declined) and lists the unresolved BLOCKING entries, which gives the counts its header and the trackers quote. With a second argument it writes the per-entry table to CSV. |

## Data, dependencies, reproducibility

Apart from `07_task_durations.R`, `les_participant_key()` and `08_lab_logs.R`, these
modules read no data of their own. They resolve
paths into `../../data/`, which is read-only, and into each paper's `results/` and
`data_derived/`. Their package dependencies are brms, cmdstanr and Stan, plus `here`,
`posterior`, `bayesplot` and `ggplot2`, which draws the posterior and prior predictive
check figures, the manuscript theme, the participant-flow diagram and the duration
figures. The manuscript helpers also use `scales` (installed with ggplot2) and `knitr`,
and `les_flow()` uses `systemfonts`, when it is installed, to measure the text of a
"Not analysed" box that has to widen.
`07_task_durations.R` and `08_lab_logs.R` add `dplyr`, `readr` and `tidyselect`, the
sparse-checkout fallback of `03_data_manifest.R` needs a `git` executable on the path, and
`les_check_lockfile()` reads `renv.lock` with `jsonlite`. The R packages, including the optional
`depictr` and `papaja`, are all pinned in `../../renv.lock` at the versions the cluster
library holds.
`01_bayesian_settings.R` stops with a pointer to `../install_bayesian_dependencies.R` if
brms is missing.

Functions are documented in plain `#` comment blocks above each definition, giving the
arguments, the value returned, the files read or written and any use of random numbers.
No roxygen2 documentation is built from them.

For the full picture — where the data live, how the environment is provisioned, and the
order the stages run in — see [`../README.md`](../README.md) and each paper's readme.
